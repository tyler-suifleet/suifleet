# SF-307 optional Walrus runtime: parse safety and explicit limits

Recorded by Claude (claude-opus-5-5) on 2026-11-24 on branch
`work/suifleet/sf-307-0eebd125`. These are local OpenEmbedded parse/task
results on the WSL host, not hardware, image-boot or publication evidence.

## Change

- `suifleet-walrus-codec` has a parse-time guard. If any `file://` codec
  input is missing from `FILESPATH`, the recipe is skipped and the reason
  names the missing files. It no longer stops parsing for every target.
  An explicit request for the codec fails with that reason. Remote inputs are
  left to the fetcher's `sha256sum` and `do_verify_codec`.
- The codec and `suifleet-node` are skipped, with a reason, on any target
  other than AArch64 with `TCLIBC = "glibc"`. `COMPATIBLE_HOST` alone also
  accepts `aarch64-*-linux-musl`. There is no fallback to another libc,
  architecture or source.
- This change does not touch any pin line: the daemon/codec `SRC_URI`,
  checksums, `SRCREV` and codec revision are unchanged. Per the boundary in
  [#820](https://github.com/tyler-suifleet/suifleet/issues/820), SF-295 owns
  the public pins and their publication.

## Limits

- Until SF-295 merges its public pins, the committed default codec source is
  still the developer-local form. Enabling the codec without those five files
  now fails with a clear skip reason instead of breaking every parse. The
  default public-input path is SF-295's pin change, and the result above
  exercises that published input through a test bbappend.
- Only Scarthgap was run. Wrynose was not run here.
- The core-client build restored 3832 of 4463 tasks from the SF-025
  shared-state, which was built with the integration layer. Restored
  dependency recipes, such as OpenSSL, did not re-execute without its fixes.
- Enabled optional archive packages building from public inputs as the
  committed default depends on SF-295 (#820, PR #841) merging its public codec
  pins. SF-307 acceptance item 2 is not complete until that combined pin is
  rebuilt on the declared profiles.
- Old userspace or an old kernel was not tested. The libc guard is a
  build-time `TCLIBC` check, not a runtime glibc-version probe.
- No image was assembled or booted, and there was no QEMU or hardware run.
  Physical Pi acceptance stays in SF-031/#32. Mainnet and production-provider
  acceptance stay in SF-087/#159.
- No repository publication, index listing or public-testnet transaction is
  claimed.
