# Storage quote recovery and honest remaining terms

Customer walkthrough testing found two independent problems: a new fleet has no
optional settings record, and React Query rejects an undefined successful result;
and historic genesis timing does not establish a current calendar expiry date.
The hook now maps a successfully absent record to null, while genuine read failures
remain errors. Refresh retries active budget/settings/schedule/price/storage reads
without uploading, signing, or clearing file selection. Concurrent refresh clicks
are guarded. Remaining terms use authoritative current/end periods and explicitly
approximate current timing, preserving longer prepaid coverage. Extensions are
admitted by actual network periods, not an inferred calendar date.

  anchor, optional verified anchor, past historic timestamp with future end period,
  duration changes, expiry warnings, SDK extension construction and upload retries.
- `node scripts/test_storage_errors.cjs`: passed missing records versus real failures
  and safe customer error rendering.
- `CHROME_EXECUTABLE=… node scripts/test_release_quote_browser.cjs`: passed real
  React Query hook/control at 390 and 1440 pixels, persistent failure then recovery,
  unchanged selected file/period, and zero upload/payment writes. Only external
