How it works

Choose the software your devices should run, send an update to the right devices, and check each result. Your team uses a web console; a small SuiFleet client on each device checks for updates and reports what happened.

What you need for a first update

  • A device and an installer. Install the SuiFleet client on a supported platform. Your platform supplies the commands that install and run your application or system update.
  • An account approval app. A wallet such as Slush is the app you use to sign in and approve changes. You do not need to manage the underlying contracts to use the console.
  • Device capacity and network funds. Your account needs room for the device, and network activity needs funds. These are separate: adding funds does not increase your device limit. The public preview uses test tokens, not real-money payments.
  • A software release to try. Start with a non-sensitive test application and one device before using groups or a wider rollout.

From registration to a running release

  1. Connect the device. The client creates the device's own identity. Register its public address and give it a recognizable name. For manufacturing batches, reserve names and serial numbers and give each device its own single-use enrollment credential.
  2. Prepare a version. Choose a component name, version, target platform, software file and installation instructions. Publishing adds the version to your library; it does not install it anywhere.
  3. Choose who can read it. Use confidential delivery for proprietary software and create an access policy before publishing. Public examples are readable by anyone. A policy controls access to private files; deployment permissions control who may send an update.
  4. Send the update. Select a device or group and approve the deployment. Start with a pilot group and use a staged rollout when you want to observe results before admitting more devices.
  5. Check the result. A deployment-created message confirms the request, not installation on every device. Follow each device's result, running version and available diagnostics. Health is the latest reported state, not a live connection test.

Your platform stays in control

SuiFleet can deliver application or system-update files and invoke your configured installer, including tools such as SWUpdate or RAUC. Your platform decides how partitions, reboot, boot confirmation and rollback work. SuiFleet does not infer those choices for you.

A verified report identifies the device that sent it. It does not prove that the hardware is uncompromised or that every part of an operating-system update succeeded. Continuous telemetry can continue through your existing tools.
