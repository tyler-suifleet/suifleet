Before your first update

A device and an installer

Install the SuiFleet client on a supported platform. Your platform supplies the commands that install and run your application or system update.

Client installation requirements ↗
  1. Install the SuiFleet client on a supported platform. Your platform supplies the commands that install and run your application or system update.
  2. A wallet such as Slush is the app you use to sign in and approve changes. You do not need to manage the underlying contracts to use the console.
  3. Your account needs room for the device, and network activity needs funds. These are separate: adding funds does not increase your device limit. The console shows the required balances and asks for approval before changes.
  4. Start with a non-sensitive test application and one device before using groups or a wider rollout.

From release to result

Connect the device

The client creates the device's own identity. Register its public address and give it a recognizable name. For manufacturing batches, reserve names and serial numbers and give each device its own single-use enrollment credential.

Continue with the product guide →
  1. The client creates the device's own identity. Register its public address and give it a recognizable name. For manufacturing batches, reserve names and serial numbers and give each device its own single-use enrollment credential.
  2. Choose a component name, version, target platform, software file and installation instructions. Publishing adds the version to your library; it does not install it anywhere.
  3. Use confidential delivery for proprietary software and create an access policy before publishing. Public examples are readable by anyone. A policy controls access to private files; deployment permissions control who may send an update.
  4. Select a device or group and approve the deployment. Start with a pilot group and use a staged rollout when you want to observe results before admitting more devices.
  5. A deployment-created message confirms the request, not installation on every device. Follow each device's result, running version and available diagnostics. Health is the latest reported state, not a live connection test.

Your platform stays in control

Your installer

SuiFleet can deliver application or system-update files and invoke your configured installer, including tools such as SWUpdate or RAUC. Your platform decides how partitions, reboot, boot confirmation and rollback work. SuiFleet does not infer those choices for you.

Continue with the product guide →
  1. SuiFleet can deliver application or system-update files and invoke your configured installer, including tools such as SWUpdate or RAUC. Your platform decides how partitions, reboot, boot confirmation and rollback work. SuiFleet does not infer those choices for you.
  2. A verified report identifies the device that sent it. It does not prove that the hardware is uncompromised or that every part of an operating-system update succeeded. Continuous telemetry can continue through your existing tools.

Behind the console

Web console

Register devices, prepare releases, control access and review results. The console runs in your browser; the site serves static files.

Technical service reference ↗
  1. Register devices, prepare releases, control access and review results. The console runs in your browser; the site serves static files.
  2. Verify releases, invoke your installer and send device-authenticated reports. The client runs on each supported device. Installation and service setup depend on the platform.
  3. Record permissions, deployments and device reports. Network transactions require approval and fees. Public network providers run this service; SuiFleet does not operate a fleet application server.
  4. Store release files and device archives; control decryption of confidential content. Storage and key-service providers run these services. Storage has a retention period and may need renewal.
  5. These services still need internet access, funding and suitable providers. “No SuiFleet application server” does not mean there are no external services or operating costs.
